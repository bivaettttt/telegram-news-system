# Telegram News System — Upgrade v3

## Что сделано

### 1) Профессиональная архитектура источников
Добавлен единый реестр `app/config/sources.yaml`.

Теперь у каждого источника есть:
- `category_hint`
- `country_hint`
- `language_hint`
- `priority_weight`
- `trust_score`
- `clusters`
- `target_channels`
- `poll_interval_minutes`
- `tags`
- `dedup_scope`

Это позволяет управлять источниками не через хаотичный Python-список, а через нормальный конфиг.

### 2) Реестр и runtime-метаданные
Добавлен `app/sources/registry.py`.

Он:
- читает `sources.yaml`
- нормализует дефолты
- отдает метаданные по `name/url`
- дает bias для классификации
- дает priority/trust для дедупа и ранжирования
- дает routing hints для world/economy канала

### 3) Сидер источников теперь синхронизируется с YAML
`app/db/seed_sources.py` больше не хранит список вручную.

Теперь сидер:
- создает новые источники
- обновляет существующие
- держит базу в согласованном состоянии с `sources.yaml`

### 4) Улучшен роутинг по каналам
`app/tasks/build_posts.py` теперь учитывает:
- категорию новости
- source target channels
- source priority
- freshness
- наличие медиа
- длину summary

То есть посты в экономический канал теперь лучше приоритизируются именно из банковских, биржевых, макро и регуляторных источников.

### 5) Улучшена классификация
`app/processing/classifier.py` теперь учитывает не только ключевые слова, но и source bias:
- `economy`
- `world`
- `geo`
- `war`

Это особенно полезно для спорных новостей, где текст сам по себе недостаточно четкий.

### 6) Улучшен дедуп
`app/processing/deduplicator.py` и `app/tasks/deduplicate_news.py` теперь делают:
- нормализацию title
- partial/fuzzy matching
- Jaccard-похожесть по токенам
- canonicalization URL без `utm_*`
- выбор более сильного кандидата по `quality + source priority + source trust`

### 7) Quality scoring учитывает качество источника
`app/tasks/quality_check_news.py` и `app/processing/quality_filter.py` теперь добавляют source-weight в quality score.

Это нужно, чтобы условный пресс-релиз ЦБ или сильная лента Интерфакса выигрывали у слабых фидов при конкуренции за публикацию.

## Что делать после распаковки

1. Обновить зависимости:
```bash
pip install -r requirements.txt
```

2. Синхронизировать источники:
```bash
python -m app.db.seed_sources
```

3. Запустить pipeline:
```bash
python -m app.tasks.pipeline
```

## Следующий логичный этап

Следующий сильный шаг — не просто расширять RSS, а добавить:
- event clustering по одной теме из 2–5 источников
- source diversity rule в одном посте
- template engine под разные типы новостей (`breaking`, `macro`, `rates`, `markets`, `banks`)
- importance ranking для выдачи в канал
- белые/черные списки по доменам и конкретным рубрикам
- market snapshot blocks (индексы / нефть / доллар / доходности)

Это уже даст не просто лучшее наполнение, а реально редакционный уровень продукта.
